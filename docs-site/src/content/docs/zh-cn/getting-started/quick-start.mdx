有两种入口：

- **使用已有部署**——同事的或托管的控制面，例如 `https://sbx.sorenforge.com`。
  你需要一个 base URL 和一把 `sbx_` API 密钥。
- **自托管**——在自己的 Modal workspace 部署控制面，约 10 分钟。

<Tabs>
<TabItem label="使用已有部署">

## 1. 获取 API 密钥

向运维索取一把 `sbx_` 密钥；如果你能访问控制台，也可以在「设置 → API 密钥」
里自己创建。然后：

```bash
export SBX_BASE_URL=https://sbx.sorenforge.com
export SBX_API_KEY=sbx_...
```

## 2. 运行任务

```bash
curl -X POST "$SBX_BASE_URL/v1/tasks" \
  -H "Authorization: Bearer $SBX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": {"text": "Write hello.txt containing hi"},
    "source": {"repo": "https://github.com/owner/repo"},
    "delivery": {"pull_request": {}}
  }'
```

或用 [Python SDK](/zh-cn/reference/python-client/)：

```python
from sbx.sdk import SbxClient

client = SbxClient()  # 读取 SBX_BASE_URL + SBX_API_KEY
created = client.tasks.create(
    "Write hello.txt containing hi",
    source={"repo": "https://github.com/owner/repo"},
    delivery={"pull_request": {}},
)
task = client.tasks.wait(created.task.id)
print(task.status)
```

## 3. 在控制台中观看

在浏览器打开部署地址，或在配置了 CLI 的机器上执行 `sbx open`。任务页会实时
推送运行过程，并展示已交付的 revision、diff 与 pull request。

</TabItem>
<TabItem label="自托管到 Modal">

## 前置条件

- Python ≥ 3.12
- [uv](https://docs.astral.sh/uv/)（通用 Python 包管理器）
- git
- [Modal 账号](https://modal.com)（免费层可用）
- 至少一个 provider CLI 已安装并在本地登录

## 1. 克隆和设置

<Steps>

1. 克隆仓库：
   ```bash
   git clone https://github.com/soren-labs/sbx-browser.git
   cd sbx-browser
   ```

2. 安装依赖：
   ```bash
   uv sync
   ```

3. 使用 Modal 认证：
   ```bash
   uv run modal token new
   ```
   这会创建交互式会话。或者在环境中导出 `MODAL_TOKEN_ID` 和 `MODAL_TOKEN_SECRET`（两者必须）。

4. 初始化配置：
   ```bash
   uv run sbx init --providers codex,devin
   ```
   创建 `~/.config/sbx/config.toml` 并扫描已安装的 provider CLI。将 `--providers` 改为你拥有的（逗号分隔：`codex`、`devin`、`antigravity`、`grok`、`opencode`）。

</Steps>

## 2. 连接 provider 账号

每个任务会在 Modal 沙箱中运行 provider CLI，使用你一次性捕获的凭证。最简单的
方式是 `sbx auth`：它执行 provider 的官方登录并导入结果：

```bash
uv run sbx auth login --provider devin
```

不想重新登录、直接复用已有登录：

```bash
uv run sbx auth import-existing --provider devin \
  --from ~/.local/share/devin/credentials.toml
```

常见凭证位置：

| Provider | 登录命令 | 凭证文件 |
| --- | --- | --- |
| Codex | `codex login` | `~/.codex/auth.json` |
| Devin | `devin`（交互式） | `~/.local/share/devin/credentials.toml` |
| Antigravity | `agy`（OAuth） | `~/.gemini/antigravity-cli/antigravity-oauth-token` |
| Grok | `grok login` | `~/.grok/auth.json` |
| OpenCode | `opencode auth login` | `~/.local/share/opencode/auth.json` |

`uv run sbx auth status` 会列出发现的凭证与各账号状态；详见
[账号与凭证](/zh-cn/guides/accounts/)。

## 3. 部署

<Steps>

1. 部署控制面与镜像：
   ```bash
   uv run sbx deploy
   ```
   这会：
   - 构建运行时镜像（每个 provider 一个）
   - 初始化持久 Dict（session、run、task、account 等）
   - 创建 `sbx-control` Modal App
   - 对在线控制面做自检

   输出包含：
   - `SBX_BASE_URL`：控制面地址
   - `sbx_<key>`：新的 API 密钥（写入 `~/.local/state/sbx/bootstrap.key`，权限 0600）

2. 验证部署：
   ```bash
   uv run sbx doctor
   ```
   应全部通过。

</Steps>

## 4. 运行首个任务

<Steps>

1. 导出 API 密钥与 base URL：
   ```bash
   export SBX_BASE_URL=<sbx deploy 输出的地址>
   export SBX_API_KEY=$(cat "${XDG_STATE_HOME:-$HOME/.local/state}/sbx/bootstrap.key")
   ```

2. **用 curl：**
   ```bash
   curl -X POST "$SBX_BASE_URL/v1/tasks" \
     -H "Authorization: Bearer $SBX_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "prompt": {"text": "Write hello.txt containing hi"},
       "execution": {"provider": "codex"}
     }'
   ```

3. **用 Python SDK：**
   ```python
   from sbx.sdk import SbxClient

   client = SbxClient()  # 读取 SBX_BASE_URL + SBX_API_KEY
   created = client.tasks.create(
       "Write hello.txt containing hi",
       execution={"provider": "codex"},
   )

   # 通过 SSE 实时观看事件
   for event in client.watch(created.agent.id, created.run.id):
       print(f"{event.type}: {event.data}")
   ```

</Steps>

## 5. 追问与交付

任务空闲后，发送追问以续用同一会话：

```bash
curl -X POST "$SBX_BASE_URL/v1/tasks/{task-id}/runs" \
  -H "Authorization: Bearer $SBX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": {"text": "Now make it executable (chmod +x hello.txt)"}}'
```

该运行会复用同一沙箱并续用 provider 原生会话（例如 Codex 的 thread ID 不变）。
任务改过仓库时，用 `POST /v1/tasks/{id}/delivery` 发布结果——见
[仓库、revision 与交付](/zh-cn/guides/repositories/)。

## 6. 打开控制台

```bash
uv run sbx open        # 直接以登录态打开
```

也可以在本地对着模拟后端运行控制台（无需 Modal 凭证）：

```bash
make console-dev     # 然后打开 http://localhost:8790
```

`make console-dev` 会启动真实的本地 `/v1` 控制面，配上模拟 provider CLI 与
演示仓库，并打印一次性 API 密钥——粘贴到「连接」页即可。见
[Web 控制台](/zh-cn/guides/console/)。
