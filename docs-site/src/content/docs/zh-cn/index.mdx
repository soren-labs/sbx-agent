## 工作原理

**1. 在你的 Modal workspace 中部署一次**

一切都运行在你的账户下：control plane、sandbox、镜像、持久存储。一条 `sbx deploy` 命令创建 App，挂载凭证为 Secret，启动 control plane。

**2. 用一个 API 调用创建 agent**

`POST /v1/agents` 指定 provider（codex、devin、antigravity、grok、opencode）、model 和 account ID。Sandbox 在 provider 镜像上启动，官方 CLI 登录，run 1 立即开始。

**3. 通过 SSE 或 REST 与 agent 通信**

用 `GET /v1/agents/{id}/runs/{runId}/stream` 流式传输规范事件，或用 GET 轮询账本。后续轮是同一 agent 上的新 run，恢复原生 session。随时取消、关闭或固定 artifact。

## 不是什么

⚠️ **部署前必读。** sbx-browser 是自己 agent 的编排，不是托管服务。

- **自带 Modal：** 每个 control plane 和 sandbox 运行在 *你的* Modal workspace，费用由你承担。
- **自带订阅：** Agent 用 *你的* 官方 provider 账号（Codex、Devin 等）认证。sbx-browser 不转售、不代理、不转换配额——任务在 provider 自己的 CLI 中执行。
- **无配额管理：** 我们不存储模型权重、不托管用户账号、不直接调用 provider API。你的凭证存在 Modal workspace 中，仅注入 sandbox。
