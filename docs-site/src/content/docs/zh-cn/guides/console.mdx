Web 控制台是基于公开 `/v1` API 的单页应用，围绕[任务](/zh-cn/guides/tasks/)组织：
描述要做的事，控制台会为你解析仓库、选择 Agent 并处理交付。控制台做的每件事
都是一次普通的 `/v1` 调用（带上你的 `sbx_` 密钥），所以所有操作都可以写成脚本。

控制台以静态文件形式放在 `web/` 目录（原生 ES 模块，无需构建），支持英文和
简体中文，跟随系统的浅色 / 深色主题，并适配手机宽度——导航会收成抽屉。

## 打开控制台

最快的入口是 CLI：它签发一次性授权并直接以登录态打开控制台：

```bash
sbx open          # 或 `sbx open --print` 只打印地址
```

<Steps>

1. **让 `web/` 与 `/v1` 同源提供服务。** 控制面不返回 CORS 头，所以浏览器
   必须通过同一个域名访问控制台和 `/v1`。可选的 [Cloudflare 边缘](/zh-cn/self-hosting/edge/)
   正是这样做的：把 `web/` 作为静态资源提供，并原样转发 `/v1/*` 及你的
   `Authorization` 头。任何能提供 `web/` 并转发 `/v1/*` 的反向代理都可以。

2. **用 API 密钥连接。** `sbx deploy` 会把一个 admin 密钥写入
   `~/.local/state/sbx/bootstrap.key`；管理员可以在「设置 → API 密钥」中
   创建更多密钥。控制台会先用 `GET /v1/me` 校验密钥再保存。

3. **选择密钥的保存方式。** 默认保存在 `sessionStorage`，关闭标签页即失效；
   勾选「在此设备上记住」则保存到 `localStorage`。密钥只会发送给你连接的
   控制面。

</Steps>

和一个演示用 git 仓库，并打印访问地址和一次性密钥。提示词中包含 `hang`、
`slow`、`fail` 或 `auth` 时会触发对应的模拟场景，方便查看各种任务状态。

## 新建任务

「新建任务」是 `POST /v1/tasks` 的表单，分为五个卡片：

| 卡片 | 设置内容 |
| --- | --- |
| **任务** | 要 Agent 做什么（提示词）和可选标题。 |
| **仓库** | `source.repo` 与 `source.ref`——起点会自动解析为精确 commit；留空则是普通沙箱任务。 |
| **AI** | provider、模型、账号与推理强度——「自动」会挑选有空闲槽位的 provider 和账号；模型选项实时显示空闲账号数。 |
| **结果** | 交付方式：「仅回复」「推送到分支」或「创建 PR」，以及分支名、PR 标题/目标与草稿开关。 |
| **高级** | 工作流绑定、结构化输出契约（严格或警告）、CPU/内存、白名单内的 Modal Secret 与空闲超时。 |

输入时会用 `POST /v1/tasks/preflight` 做就绪检查；检查失败会显示在提交按钮
上方并阻止提交，直到通过。创建请求携带 `Idempotency-Key`，重复点击也不会
创建两个任务。

## 观看与引导任务

任务页展示目标、解析出的 provider/模型/仓库，以及实时状态——「排队中」
「进行中」「可发布」「发布中…」「交付失败」「已完成」「失败」「已取消」
或「已过期」。三个标签页：

- **对话**——每次运行实时推送的过程：Agent 消息、带输出与退出码的命令、
  文件改动与思考过程，以及用量面板（token、预估成本、沙箱时间）。
- **变更**——revision 流水线（见下）。
- **详情**——原始任务记录与各种 ID。

<figure class="sbx-shot">
  <Image src={task} alt="已完成任务：对话标签页与用量面板" />
  <figcaption>运行过程实时推送；命令与文件改动可折叠。</figcaption>
</figure>

- 在对话输入框**追问**：<kbd>Enter</kbd> 发送，<kbd>Shift</kbd>+<kbd>Enter</kbd>
  换行。任务会保留沙箱并续用 provider 原生会话；任务忙碌时消息会排队。
- **重试**会重新运行已完成/失败的任务，或重试失败的发布——按钮文案表明
  将要做的操作（仅交付失败时显示「重试发布」）。
- **取消**停止进行中的运行；关闭对话面板后任务历史变为只读。

## 变更：revision、评审与合并

「变更」标签页跟踪每个 revision 的流水线——Revision → 已交付 → 已评审 →
已合并——附精确 sha、文件 diff、交付记录（分支与 PR）和已记录的评审。

## 集成

「集成」页是连接 provider 账号与 GitHub 的地方——见
[账号](/zh-cn/guides/accounts/)与 [GitHub 集成](/zh-cn/integrations/github/)。

- **连接 provider** 提供 provider 的官方登录，或一个本地配对票据——在已登录
  的机器上执行 `sbx auth pair <ticket>` 完成。「账号」视图列出每个账号的状态、
  槽位占用与模型。
- **GitHub** 显示是否已配置 GitHub App 以及每个安装覆盖的仓库；
  `sbx github connect` 会打开 App 的安装页面。「同步」从 GitHub 刷新，
  「吊销」移除安装。

## 设置

- **API 密钥**：创建带或不带 `admin` 的密钥。明文只显示一次，控制面只保存
  sha256；吊销当前使用的密钥会立即退出登录。
- **容量**：每个已启用 provider 提供的模型、空闲账号数与支持的推理强度；
  admin 密钥还能看到槽位占用。
- **运行时**：控制面与 CLI 的版本信息。
- **偏好**：语言、主题，以及清除本地记住的提示词。

## 高级页面

侧边栏的「高级」区展示任务所解析到的底层资源——用于调试，以及任务界面
未覆盖的流程。

- **Agent**——当前密钥创建的所有 Agent，带实时状态、provider、模型、token
  与成本；打开可查看其运行、工作区与 git 操作（即任务页展示的同一批记录，
  只是更底层）。「新建 Agent」是 `POST /v1/agents` 的表单，包括精确
  `base_sha` 与 handoff 起点——见 [Agent 与运行](/zh-cn/guides/agents-and-runs/)。
- **工作流**——绑定 `workflow_id` 的 Agent 的恢复视图：进度、每个任务的
  角色/Agent/最近一次运行、子任务缩进显示。「关闭工作流」只关闭你的密钥下
  绑定到该工作流的 Agent。
- **产物**——沙箱销毁后依然存在的持久快照（`patch.diff`、git bundle、带
  sha256 的文件）。产物可按成员下载，也可交接给新 Agent——见
  [产物与交接](/zh-cn/guides/handoffs-and-artifacts/)。

## 配置

只要控制台与 `/v1` 同源部署，就不需要任何配置。如有需要，可以在 `app.js`
加载前用脚本设置两个可选的全局变量：

| 全局变量 | 作用 |
| --- | --- |
| `window.SBX_API_BASE` | 「连接」页上默认填入的控制面地址。 |
| `window.SBX_DOCS_URL` | 你自己托管的本文档站点的根地址。设置后，控制台里的帮助链接会直接打开对应页面（中文界面打开中文页面）；未设置时链接到 GitHub 上的文档源码。 |

## 常见问题

| 现象 | 排查方向 |
| --- | --- |
| 被带回「连接」页并提示密钥被拒绝 | 密钥已被吊销或输入有误，请在「设置 → API 密钥」中新建。 |
| 「无法连接到控制面」 | 控制台与 `/v1` 不同源，或地址有误，参见 [边缘部署](/zh-cn/self-hosting/edge/)。 |
| 运行显示「正在重新连接事件流…」 | 事件流中断后控制台会自动续传；若放弃，仍会轮询运行记录直到结束。 |
| 「提示词来自其他客户端」 | 该运行由其他客户端发起，API 不保存提示词文本。 |
