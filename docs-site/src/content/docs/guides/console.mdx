The web console is a single-page app for the public `/v1` API, organized
around [tasks](/guides/tasks/): describe the work, and the console resolves
the repository, the agent and the delivery for you. Everything it does is an
ordinary `/v1` call with your `sbx_` key, so anything you can do in the
console you can also script.

It ships as static files in `web/` (plain ES modules, no build step), speaks
English and Simplified Chinese, follows your system's light or dark theme,
and works at phone widths — the navigation collapses into a drawer.

## Open the console

The fastest way in is the CLI, which mints a one-time grant and hands off
already signed in:

```bash
sbx open          # or `sbx open --print` to get the URL only
```

<Steps>

1. **Serve `web/` on the same origin as `/v1`.** The control plane does not
   send CORS headers, so the browser must reach the console and `/v1` through
   one origin. The optional [Cloudflare edge](/self-hosting/edge/) does
   exactly this: it serves `web/` as static assets and forwards `/v1/*` with
   your `Authorization` header untouched. Any reverse proxy that serves
   `web/` and forwards `/v1/*` works the same way.

2. **Connect with an API key.** `sbx deploy` writes an admin key to
   `~/.local/state/sbx/bootstrap.key`; admins can mint more under
   **Settings → API keys**. The console checks the key with `GET /v1/me`
   before saving it.

3. **Choose how long the key is kept.** By default it lives in
   `sessionStorage` and is forgotten when the tab closes. **Remember on this
   device** moves it to `localStorage`. The key is only ever sent to the
   control plane you connected to.

</Steps>

<Aside type="tip" title="Try it without a cloud account">
`make console-dev` starts the real control plane with a local backend, fake
provider CLIs and a demo git repository, then prints a URL and a throwaway
key. Prompts containing `hang`, `slow`, `fail` or `auth` trigger the matching
fake scenario, so you can see every task state.
</Aside>

Keys without the `admin` scope can use everything except the account and
key-management surfaces under **Integrations** and **Settings**, which show a
lock instead.

## Create a task

**New task** is the `POST /v1/tasks` form, in five cards:

| Card | What it sets |
| --- | --- |
| **Task** | What the agent should do (the prompt) and an optional title. |
| **Repository** | `source.repo` and `source.ref` — the starting point resolves to an exact commit for you. Leave empty for a plain sandbox task. |
| **AI** | Provider, model, account and reasoning effort — `Automatic` picks a provider and account with a free slot. Model choices show live free-account counts. |
| **Result** | Delivery: **Report only**, **Push to a branch** or **Open a pull request**, with branch name, PR title/target and draft toggle. |
| **Advanced** | Workflow binding, a structured-output contract (strict or warn), CPU/memory, allow-listed Modal secrets and idle timeout. |

A readiness check runs `POST /v1/tasks/preflight` as you type; a failing
check is shown above the submit button and blocks submission until it
passes. The console sends an `Idempotency-Key` with the create call, so a
double click never starts two tasks.

## Watch and steer a task

A task page shows the goal, the resolved provider/model/repository, and a
live status — **Queued**, **Working on it**, **Ready to publish**,
**Publishing…**, **Delivery failed**, **Finished**, **Failed**,
**Cancelled** or **Expired**. Three tabs:

- **Conversation** — each run's streamed activity: agent messages, commands
  with output and exit codes, file changes and reasoning, plus a usage panel
  (tokens, estimated cost, sandbox time).
- **Changes** — the revision timeline (see below).
- **Details** — the raw task record and identifiers.

<figure class="sbx-shot">
  <Image src={task} alt="A finished task with the conversation tab and usage panel" />
  <figcaption>Runs stream live; commands and file changes collapse.</figcaption>
</figure>

- **Follow up** from the conversation box: <kbd>Enter</kbd> sends,
  <kbd>Shift</kbd>+<kbd>Enter</kbd> adds a line. The task keeps its sandbox
  and resumes the provider's native session; a busy task queues the message.
- **Retry** re-runs a finished/failed task or retries a failed publish —
  the button is labelled for what it will do (**Retry publish** when only
  delivery failed).
- **Cancel** stops the in-flight run. Closing the conversation panel leaves
  the task's history read-only.

## Changes: revisions, review and merge

The **Changes** tab tracks each revision's pipeline — Revision → Delivered →
Reviewed → Merged — with the exact shas, the file diff, the delivery record
(branch and pull request) and recorded reviews.

<figure class="sbx-shot">
  <Image src={changes} alt="The changes tab with a delivered revision, diff and pipeline" />
  <figcaption>Every step is pinned to an exact sha.</figcaption>
</figure>

- **Publish now** appears when a revision is ready but not delivered;
  **Review changes** opens the delivered result.
- **Add review** records a verdict pinned to the revision's head. A review
  turns **Stale** when a newer revision materializes — review again.

<figure class="sbx-shot">

  <figcaption>Reviews pin an exact head; a newer revision marks them stale.</figcaption>

- A publish that fails surfaces the structured delivery error and offers
  **Retry publish** — the run is not re-executed.

## Integrations

**Integrations** is where provider accounts and GitHub get connected — see
[Accounts](/guides/accounts/) and
[GitHub integration](/integrations/github/).

- **Connect provider** offers the provider's hosted login, or a local-pair
  ticket you complete on a machine that is already logged in with
  `sbx auth pair <ticket>`. The **Accounts** view lists every account's
  status, slot usage and models.
- **GitHub** shows whether a GitHub App is configured and which repositories
  each installation covers; `sbx github connect` opens the App's install
  page. **Sync** refreshes from GitHub, **Revoke** removes an installation.

## Settings

- **API keys** — create keys with or without `admin`. The plaintext is shown
  exactly once; the control plane keeps only its sha256. Revoking the key
  you are using signs you out.
- **Capacity** — the models each enabled provider advertises, free-account
  counts and supported reasoning efforts; admin keys also see slot usage.
- **Runtime** — control-plane and CLI version details.

## Advanced pages

The sidebar's **Advanced** section exposes the layer tasks resolve onto —
useful for debugging and for flows the task surface does not cover.

- **Agents** — every agent your key created, with live status, provider,
  model, tokens and cost; open one for its runs, workspace and git actions
  (the same records a task page renders, at the lower level). **New agent**
  is the `POST /v1/agents` form, including an exact-`base_sha` pin and
  handoff starting points — see
  [Agents and runs](/guides/agents-and-runs/).
- **Workflows** — the recovery view for agents bound to a `workflow_id`:
  progress, each task's role/agent/latest run, child tasks under parents.
  **Close workflow** closes exactly that workflow's agents under your key.
- **Artifacts** — durable snapshots (`patch.diff`, git bundle, collected
  files with sha256) that outlive the sandbox. An artifact can be downloaded
  member by member or handed off to a new agent — see
  [Artifacts and handoffs](/guides/handoffs-and-artifacts/).

## Configuration

The console needs no configuration when it is served next to `/v1`. Two
optional globals can be set in a script before `app.js` loads:

| Global | Effect |
| --- | --- |
| `window.SBX_API_BASE` | Default control-plane URL shown on the Connect screen. |
| `window.SBX_DOCS_URL` | Base URL of your hosted copy of this documentation. Help links in the console then open the matching page, in Chinese when the console is in Chinese. Without it they open the docs sources on GitHub. |

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Sent back to **Connect** with "key was rejected" | The key was revoked or mistyped — or the control plane restarted: keys minted at runtime are held in memory and cleared on restart (the deploy-time bootstrap key is the durable one). Mint a new one under **Settings → API keys**. |
| "Could not reach the control plane" | The console and `/v1` are not on the same origin, or the URL is wrong. See [Edge](/self-hosting/edge/). |
| A run says "Reconnecting to the stream…" | The event stream dropped; the console resumes it. If it gives up, the run record is still polled until it finishes. |
| "Prompt sent outside this browser" | The run was started by another client; the API does not store prompt text. |
