===== sbx =====
usage: sbx [-h] [--config CONFIG] [--state-dir STATE_DIR] [--json]
           {init,credentials,config,status,deploy,doctor,smoke,upgrade,open,github,uninstall,auth}
           ...

Deploy and operate the sbx control plane on your own Modal workspace.

positional arguments:
  {init,credentials,config,status,deploy,doctor,smoke,upgrade,open,github,uninstall,auth}
    init                check prerequisites and write config
    credentials         scan selected providers' local credential files (never
                        prints contents)
    config              show resolved non-sensitive config
    status              show deployment status
    deploy              idempotent deploy of the control plane
    doctor              verify the deployment end to end
    smoke               run a minimal /v1 agent to terminal
    upgrade             redeploy preserving durable stores
    open                open the Console in a browser via a one-time grant
                        handoff
    github              GitHub integration: connect ( default one-click
                        install)
    uninstall           stop app and terminate sbx sandboxes
    auth                provider auth:
                        login/status/verify/relink/logout/import-existing

options:
  -h, --help            show this help message and exit
  --config CONFIG       config file path (default: $SBX_CONFIG or XDG)
  --state-dir STATE_DIR
                        state dir (default: $SBX_STATE_DIR or XDG)
  --json                machine-readable output

===== sbx auth =====
usage: sbx auth [-h] [--config CONFIG] [--state-dir STATE_DIR] [--json]
                {status,login,import-existing,verify,relink,pair,logout} ...

positional arguments:
  {status,login,import-existing,verify,relink,pair,logout}
    status              local credential scan + per-account auth-session
                        states
    login               run the provider's official CLI/OAuth login, then
                        capture + verify
    import-existing     capture credential files a vendor login already wrote
                        (no token paste)
    verify              run the cloud auth probe; promotes the account on a
                        pass (remote /v1 probe when a deployment is
                        configured, else local)
    relink              re-capture → refresh → verify; restores scheduler
                        eligibility
    pair                pair this host's provider login with a cloud connect
                        session ( ): run the vendor login, post the
                        captured blob
    logout              sign out: drop credential material, flip to unverified

options:
  -h, --help            show this help message and exit
  --config CONFIG       config file path (default: $SBX_CONFIG or XDG)
  --state-dir STATE_DIR
                        state dir (default: $SBX_STATE_DIR or XDG)
  --json                machine-readable output
