# SOR-101 independent security review (Release 0.1 gate)

Base `e1fd427` → reviewed HEAD `f329d02`, plus the review-fix commit on top.
Scope: SOR-101 security release gate incl. closing evidence for SOR-55 and
SOR-56. Reviewer acted as independent SWE: verified the diff, ran the gate
tests under a credential-laden canary env, and fixed one blocker below.

## Blocking defect found and fixed in this review commit

1. **SSE/event-stream redaction missed most injected credential shapes.**
   `runtime.runner.events.redact_text` covered only `sk-…` and `Bearer …`.
   Provider error text is `redact_obj`'d into `events.jsonl`, which
   `control.app` tails verbatim into the public SSE stream
   (`/api/sessions/{id}/events`), and `turns/<n>.json.error` flows to the
   public `run.error.message`. A provider echoing an OAuth JWT
   (`CODEX_AUTH_JSON` tokens are JWTs), an `sbx_` key, `xai-`, `ghp_`/
   `github_pat_` (the `SBX_GITHUB_EPHEMERAL` path forwards `GH_TOKEN`),
   `lin_api_`/`lin_oauth_` (Linear MCP bridge), `AKIA…`, or `AIza…` key in a
   free-text message would leak it raw to SSE and the API — exactly the
   scenario SOR-101 item 4 gates ("logs/errors/SSE/event capture 不打印
   token"). `runtime.runner.events._EXTRA_SECRET_RES` now covers those
   shapes, and `control.run_errors._SECRET_RES` mirrors the same set on the
   run.error path (kept deliberately duplicated: runner must not import
   control). Regression tests:
   `test_redact_covers_injected_token_shapes` (runner, JSON + free-text
   paths), `test_error_message_redacts_injected_token_shapes` (control).

## Verified against the SOR-101 checklist

1. **Test env isolation (SOR-55/SOR-56) — PASS.** `tests/conftest.py` scrubs
   the full credential env universe at collection time (needed because
   `control.app` builds a real app at import) and re-applies per-test via
   the autouse fixture; `SBX_E2E_MODAL=1` is the documented opt-out and the
   e2e_modal conftest correctly overrides the fixture. The canary suite
   (`tests/integration/security`) proves a host shell holding
   `CODEX_AUTH_JSON`, `SBX_ACCOUNT_CREDENTIAL`, provider keys, Modal tokens,
   and `SBX_V1_BOOTSTRAP_KEY` reaches neither the sandbox auth store nor
   pytest output. `live_env` keeps a second delenv layer; item1 compares
   token digests so a failing assert cannot print the token (SOR-55).
   `LocalProcessBackend.exec` inherits only `PATH/HOME/LANG` + explicit
   `env=` (SOR-56 verified in `control/backend.py`).
2. **Sandbox env allowlist — PASS.** `sandbox_io.sandbox_env` forwards only
   the handle's provider keys; the account credential blob is scoped by
   provider AND `account_id`; `extra=` cannot re-add foreign credentials.
   Runner child env strips `CODEX_AUTH_JSON`/`SBX_ACCOUNT_CREDENTIAL` plus
   Devin/Grok auth bridges (`AGENT_ENV_EXCLUDE`).
3. **Artifact boundary — PASS.** Denylist covers provider auth dirs, HOME,
   event streams, netrc/.env/key globs at any depth; `forbidden_values` now
   extracts token/secret-shaped fields from JSON (incl. nested-JSON blob
   contents) and TOML credential docs, so a workspace file holding just a
   token fails the snapshot closed. `REDACTED`-length placeholders are not
   extracted (`_MIN_SECRET_LEN`), so fixtures can't false-positive.
4. **Logs/errors/SSE — PASS with the fix above.** Provider stderr goes to
   `turns/<n>.stderr` (denied path, never served); event text is redacted
   before `events.jsonl`/`events.raw.jsonl`; `run_errors._clip` redacts
   before truncation as the second seam.
5. **Secret storage — PASS.** `write_secret_file` opens 0600 (no
   umask-readable window), restricts the containing dir to 0700, re-pins
   mode on overwrite; used by `restore_credential_blob` and `auth.json`
   bootstrap. Registry stores metadata only.
6. **API keys — PASS.** `sbx_<token_hex(20)>`; store keeps sha256 only;
   `lookup(hash)`/`lookup(sbx_<hash>)` return nothing; revoke verified.
7. **Cross-tenant/scope — unchanged by this diff**; the ambient `/v1` model
   was not relaxed (artifact forbidden-values remain account-scoped).
8. **Repo/history scan — PASS.** `git grep` over the tree and history for
   common token patterns and credential filenames found only `REDACTED`
   placeholders, canaries, and contract docs. No `.env`/`auth.json`/key
   material tracked.
9. **Modal leftovers — honestly deferred.** No real Modal credentials in
   this environment; the e2e_modal suite (`SBX_E2E_MODAL=1`) owns live
   teardown verification. Not faked.

## Non-blocking observations

- `test_autouse_scrub_removed_credential_env` fails honestly (key names
  only, never values) if run under `SBX_E2E_MODAL=1` with real creds —
  correct behavior; e2e runs target `tests/e2e_modal` only.
- Ambient non-credential knobs (`SBX_RUNNER_CMD`, `SBX_MODAL_APP_NAME`,
  `SBX_DEVIN_ACCOUNT_ID`, `SBX_DEFAULT_MODEL`) are not scrubbed; they are
  config, not secrets, and tests set their own values via monkeypatch.
- Shape-based redaction cannot catch opaque tokens echoed without a
  recognizable prefix (e.g., a raw Modal token with no key context). The
  artifact fail-closed scan (`forbidden_values` carries the actual secret
  values, not just shapes) is the compensating control for artifacts.
- `SBX_V1_API_KEY`/`SBX_V1_BASE_URL`/`SBX_POOL_GATE_REAL` deliberately
  unscrubbed — opt-in inputs of `tests/acceptance`, outside `make test`
  testpaths; no test reads them.
- `import control.app` builds a real app with file stores under the ambient
  XDG home — pre-existing behavior; the collection scrub prevents ambient
  `SBX_*_STORE_DIR`/`SBX_BACKEND` from redirecting it.
