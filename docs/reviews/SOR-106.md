# SOR-106 — Antigravity CLI pin drift 1.2.2 → 1.2.3: contract re-validation

Base `2f46b3f`. Host `agy --version` reports `1.2.3` while
`runtime/packages.txt` pinned `agy_version=1.2.2` (SOR-60 spike-validated);
the whole-token version gates correctly failed closed. This pass re-ran the
SOR-60/SOR-62 headless contract against the real 1.2.3 binary in a local
clean room and bumped the pin.

## Method (no credential exposure)

- Fresh `HOME` (`/tmp/agy123-smoke/home`); only
  `.gemini/antigravity-cli/antigravity-oauth-token` copied in (mode 700/700/600
  — sha256-16 prefix compared, contents never printed).
- `env -i HOME=… PATH=…` with all other env stripped; `</dev/null` stdin,
  same as the runner.
- Every captured stream/artifact scanned for the token blob and each
  `id_token`/`token`/`access_token`/`refresh_token` value — **zero leaks**.

## Verdict: compatible — pin bumped, exact matching kept

- `runtime/packages.txt`: `agy_version=1.2.3`. Both gates
  (`_assert_host_cli_version` host probe, `cli_version_check` in-image
  `grep -E`) still match the pin as a **whole version token** — matching was
  not weakened; a stale 1.2.2 binary now fails the build
  (`run_gate("1.2.2","1.2.3") != 0` covered by
  `test_cli_version_check_gate_rejects_prefixed_versions`).
- No adapter changes needed: `runtime/runner/adapters/antigravity.py`
  behavior validated as-is (top-level `conversation_id`, string `error`,
  stale-resume suppression, usage map).
- Synced: pin assertions in `test_image_local.py` /
  `test_provider_images.py`, `_version_grep_pattern` docstring,
  `docs/providers.md` matrix, `CHANGELOG.md`. Dockerfiles regenerated —
  agy rides the Modal host-binary path, not the local Dockerfiles, so they
  are byte-identical. `image_manifest()` picks the pin up from
  `packages.txt` (`--manifest` verified).
