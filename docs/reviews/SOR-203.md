# SOR-203: control-plane base latency — benchmark and warm strategy

Scope: the Modal-hosted control plane's **web function** (`fastapi_app`
ASGI) only. Agent `Sandbox.create` lifecycle (native `idle_timeout` /
`timeout`, reaper bounds) is unchanged.

## Measured baseline (2026-09-24, `sbx-control-release01-rc`, workspace `sorenlab2026`)

Probe: unauthenticated `GET` on the deployed app's web URL — enough to
exercise container routing and the full request path; auth result is
irrelevant to the timing.

| Case | Result |
| --- | --- |
| Cold (pool at zero; first request after >60s idle) | 7.64s, 7.46s (n=2) |
| Warm (immediately following requests) | 0.32–0.36s (n=7) |

Modal's default idle window is 60s (`scaledown_window`), so any request
arriving more than ~1 min after the previous one pays the ~7.5s cold
start — CLI `status`/`doctor`, dashboard page loads, and `/v1` polling
bursts all hit it. The cold path is image-pull-free (image is cached in
the workspace); ~7.5s is container boot + ASGI startup.

## Strategy chosen

`scaledown_window = 300s` on `fastapi_app` (env `SBX_CONTROL_SCALEDOWN_WINDOW_S`;
config.toml `deploy.control_scaledown_window_s`), with opt-in
`SBX_CONTROL_MIN_CONTAINERS` / `SBX_CONTROL_BUFFER_CONTAINERS`
(`deploy.control_min_containers` / `deploy.control_buffer_containers`)
for operators who want always-warm or burst headroom. Default `0` keeps
scale-to-zero semantics for both count knobs.

Alternatives considered:

- `min_containers = 1`: eliminates *every* cold start including the
  first-after-idle request, but is always-on — ~35× the incremental cost
  of the default strategy below. Offered as an override, not the default.
- `buffer_containers`: helps only under concurrent load; the control
  plane already runs `modal.concurrent(max_inputs=20)`, so a burst lands
  on the warm container, not a new cold one. Opt-in only.
- Warming `reap_cron`: rejected — a `*/5` cron's own startup latency is
  irrelevant; any warmth there is pure cost.

## Incremental cost assumptions

Modal Starter list prices from `control/config.py`
(`CPU_USD_PER_CORE_S = 0.00003942`, `MEM_USD_PER_GIB_S = 0.00000667`);
the control function requests Modal's default 0.125 CPU + 128 MiB:

- Idle container-second ≈ $0.0000058 (0.125 core + 0.125 GiB)
  ≈ **$0.021/h ≈ $0.50/day if warm continuously**.
- `scaledown_window 60→300s` adds at most 240s of idle tail per quiet
  period ≈ **$0.0014 per cool-down**; e.g. ~10 bursts/day ≈ **$0.42/mo**
  incremental.
- For comparison, `min_containers = 1` ≈ **$15/mo** continuous.

Billing applies only while a container exists; `scaledown_window` costs
nothing when the deployment is unused.
