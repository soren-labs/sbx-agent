# Hosted Modal onboarding

## Real integration (SOR-290)

`control.real_modal.RealModalProvider` implements both production provisioning
and compute interfaces. Supply it as `modal_provider` and `compute_provider` to
the app factory. Every SDK lookup/build/publish/create/exec/poll/list/terminate
uses `Client.from_credentials` with the connection's own Token ID/Secret. It never
uses `Client.from_env`. Modal OAuth is deliberately unavailable; the production
UI offers manual credentials, while mock mode retains its simulated consent.

Provisioning creates the user's `sbx-compute` environment and app. Runtime image
names include a digest of the runtime source and version. Published names resolve
without rebuilding; missing names build through the user-bound App context.
Smoke verifies the installed Codex CLI and HTTP service in a real, credential-free
sandbox. Source uploads include only the runtime tree, never local auth state.

Hosted sandboxes use the persisted image id, owner/connection tags, native timeout
and idle bounds, and a TLS tunnel on port 8792. Account tokens, the database URL,
email key and operator bridges are excluded from sandbox baseline env and no
named operator secrets are mounted. Executions close stdin and use a process
group with `setsid --wait`; cancellation terminates that group and observes its
exit. The read-only HTTP service starts lazily and survives VPS reconstruction.
Native resource identity is checked against actual remote tags as well as the
PostgreSQL owner linkage. Shutdown does not destroy surviving user compute.

Run `uv run python -m deploy.hosted.gates.modal` with the protected integration
env to exercise two real workspaces against a throwaway local PostgreSQL
container. The container uses a pinned public PostgreSQL image and a random
loopback port and is removed on exit. No existing database or workload is used.
The gate covers Ready/idempotency, runtime bootstrap, real HTTPS incremental SSE,
foreign grants and actual cross-workspace SDK denial, cancellation, listener
reuse after control-plane reconstruction, cleanup and reprovision. The SSE marker
is deliberately generated by a sandbox process: this gate proves compute and
transport, not real AI inference (SOR-292).

Official SDK references: [user clients](https://modal.com/docs/sdk/py/latest/Client),
[App lookup](https://modal.com/docs/sdk/py/latest/App),
[sandbox images](https://modal.com/docs/guide/sandboxes), and
[networking](https://modal.com/docs/guide/sandbox-networking).

SOR-283 adds user-owned Modal connections and a reconcilable Codex runtime
installation. The authenticated Integrations page submits Token ID/Secret or
starts authorization. Workspace verification, `sbx-compute` namespace creation,
versioned `sbx-runtime` image publication and smoke verification update durable
PostgreSQL connection records before Ready.

Set `SBX_CONNECTIONS_MODE=mock` for the deterministic workspace adapter and build
the console with `VITE_HOSTED=1`. Configure `SBX_CONNECTION_ENCRYPTION_KEY` as a
URL-safe base64 encoded random 32-byte key, managed outside the repository.
Keep the same key across process restarts; losing it makes stored connections
unreadable. There is no insecure encryption fallback. Tokens never appear in
responses, progress or logs. AES-GCM binds ciphertext to the user, provider and
connection. Authorization states expire after ten minutes and are consumed once.

`ModalProvider` is the production adapter boundary. Each workspace/image/smoke
call receives a user-owned `ModalContext`; adapters must construct a client from
that context, without ambient operator credentials. OAuth exchange and redirect
are separate adapter operations. Without an injected configured adapter, the
production connection is explicitly unavailable. The fake exercises all steps
and independent workspaces without accessing Modal. Real SDK/OAuth integration,
image publication and smoke acceptance still require external credentials.

Provisioning uses a durable five-minute lease and optimistic versions. Repeating
a Ready installation of the current runtime makes no provider calls. Failures
retain safe progress and permit retry; expired leases permit reconciliation after
a crash. Adapter namespace/image operations must be idempotent. A concurrent
reconnect supersedes the old installation rather than overwriting its credentials.
Business state remains on the VPS PostgreSQL database.
