## Scope, reproducibility, and evidence labels

Research accessed **2026-10-05**. Public repositories were shallow-cloned (`--depth 1`) into `/home/zheng/ai-work/amp-research`, outside the SBX worktree. SHAs below pin the exact inspected contents; clone time is not a release date. No Amp source, screenshots, vendor directories, or implementation snippets are copied into this proposal. Links point to original sources.

- **C — public code evidence:** behavior visible in a pinned public repository. Public availability is separate from an open-source license.
- **D — public documentation evidence:** product behavior described by Amp; mutable pages are dated and locally hashed below. It does not reveal closed implementation.
- **S — current SBX code evidence:** inspected main at the pinned baseline; separate PR description evidence is explicitly marked.
- **I — inference/design:** an original SBX proposal derived from requirements and comparison. All target schemas/protocols/diagrams are I, unless stated otherwise.

Absence of a root license is reported conservatively; it is not proof that no grant exists anywhere. License observations are file/declaration checks, not legal opinions. No reuse is needed here even for Apache/MIT repositories. Public docs were summarized with attribution, not mirrored into SBX.

| Claim | Class / primary evidence | Consequence for proposal |
| --- | --- | --- |
| Amp has a stable user-facing work conversation distinct from location. | D: Threads, Orbs, Runners. | Session/Executor separation is a strong product match; SBX native CLI binding is I. |

## Limits and provenance

- Code inspection is source analysis, not certification of upstream runtime behavior. No Amp credentials or agent execution were used; no Amp application was deployed.
- No public evidence establishes Amp core persistence, internal session event reducers, authorization topology, exact Orb orchestration or Puck implementation. Missing evidence stays missing.
- Repo snapshots and mutable public docs represent different ages; the SDK package-name change demonstrates why examples must not be treated as current API contracts.
- Research scripts, cloned repositories, downloaded HTML and diagram-rendering dependencies live outside SBX. Only original Markdown analysis/design enters the PR.
- Target tables, state machines, routes, source tree, and Mermaid diagrams are all proposed architecture. Validation of diagrams/docs does not validate implementation feasibility; required later gates are listed in [decisions.md](decisions.md).
