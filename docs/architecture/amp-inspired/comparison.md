## 3. Overlapping state machines to delete

1. **Work identity aggregation**: SessionRecord idle/running/suspended/lost ↔ ledger CREATING/RUNNING/FINISHED/UNKNOWN ↔ Task queued/running/delivering/delivery_failed ↔ V2 Session status/phase mapping. Target has one lifecycle each for Session, Turn, Execution, lease, and Delivery; activity is a projection with no independent transition history.
2. **Remote shipping mirrors**: Workspace git policy/head/PR/merge/publish error ↔ Revision.delivery ↔ Task aggregate delivery ↔ V2 session.delivery. Target stores the effect once in Delivery and returns projections from it.
3. **Review orchestration overlays**: hosted review Session link ↔ Run output contract ↔ Revision Review record ↔ UI polling and stale/head checks. Target has one child Session/Delegation result with immutable subject; Delivery gate queries it.
4. **Restart ownership**: startup claim in Task transition ↔ lifecycle claim in sandbox tags ↔ scheduler lease ↔ watcher process map ↔ ack-thread mutation registry. Target uses resource epochs/Jobs with the same claim/fence protocol, plus runtime operation dedupe.
5. **Replay identities**: sandbox JSONL line cursor ↔ RunActivity saved transcript ↔ V2 normalized stream/status hub ↔ direct runtime grant stream ↔ Console history/cache reconciliation. Target ingests once and exposes committed Session sequence; cache is disposable.
6. **Recovery indexes/store variants**: per-agent workflow binding + workflow index + manifest scan/cache/backfill ↔ namespaced PostgreSQL mapping of older models. Target uses typed FKs/indexes. Cloud-free tests exercise PostgreSQL semantics where essential and adapter fakes, not four production persistence families.

These replacements remove duplicated **ownership**, not useful distinctions. Turn versus compute lifetime, ChangeSet versus Snapshot, and projection versus external observation remain separate because they answer different product questions.

## 4. Special flows that become ordinary operations

| Today | Generic primitive |
| --- | --- |
| Hosted reviewer must start from published branch and GET can settle review | Spawn child with immutable input; validate/publish result; Delivery separately syncs a GitHub comment. |
| Finish callback materializes Revision before ledger finalization, then voids it if cancel won | Commit terminal outcome and capture eligibility; fenced capture creates ChangeSet only when authorized, with salvage separate. |
| Automatic publication discovered by scanning workspace + Revision + FINISHED | Transactionally enqueue Delivery intent after eligible capture. Reconciliation recovers that same intent. |
| Stale lifecycle sweep must preserve queued messages through credential scrub | Worktree barrier + current lease epoch; Messages remain in DB, not the filesystem checkpoint. |
| Startup reconstruction turns prior unbound accepted Sessions into retry errors | Expired Job claim is reconciled/reclaimed; actual unrecoverable failures become explicit preparation errors. |
| Retry endpoint guesses whether to rerun code or republish | Retry resource is explicit: Turn retry versus Delivery retry versus checkpoint restore. |
| Workflow recovery needs API key + workflow ID and derives missing Run verdicts | Query parent/child Session relations and their durable results; unresolved attempt stays unknown. |

## 5. What remains uniquely SBX

Official CLI distribution, version/capability testing, credential portability/refresh, native context state, provider cancellation semantics, and truthful event normalization remain SBX responsibilities. Harness selection and Executor selection are independent. Multiple provider Connection limits, owner-bound Modal clients, no ambient credential fallbacks, and native thread resume checks cannot be deleted for an Amp-like UI.

Do not copy Amp's own prompt/tool/model routing implementation, direct-trunk Ship default, voice/multiplayer/shared billing, hosted Git service, Portal DOM widget, or Substrate/Kubernetes operations simply because they exist publicly. The comparison supports a smaller product vocabulary; it does not justify taking ownership of provider model inference.
